# Testnet

`nvnm-tempo-testnet-1` (EVM Chain ID `787223`) is a fork of [Tempo](https://github.com/tempoxyz/tempo) — `reth` execution + Commonware Simplex BFT consensus. Peering is configured via `reth`'s `--trusted-peers` flag with `enode://` URLs. See [Network Details](/resources/network-details) for RPC/explorer endpoints.

**Public Peers** (externally reachable)

```
enode://f5826a55ca7c92dc04e6da41e061b0b684ae0338bcdec81ed3213ae8b251308b6870ddafee5128ba16268bdff78f2eba8bda6518d175ddc0cd36c606d604f526@34.150.20.80:30303
enode://2d91f00d8305eb5faf7a002a260ac0d83b6ac4b1a61de7cbdf4021b4476a03360db071e6842f4d3d176c90d9a12c264d77e6c3792634a09a4f483bbceb5c8d70@34.92.172.118:30303
```

**P2P Port**: `30303` (used for both peer connections and discovery)

To run a node that syncs NVNM Chain testnet using these peers:

<Note title="Testnet chain spec coming soon">
  `--chain` must point to the `nvnm-tempo-testnet-1` chain specification (genesis) file. Without it, `tempo node` defaults to Tempo `mainnet` and will not join NVNM Chain testnet. The chain spec file will be published soon.
</Note>

1. Generate an ed25519 signing key file. `--consensus.signing-key` takes a **file path**, not a hex key:

```bash
tempo consensus generate-signing-key --output ./signing.key
```

2. Start the node with the testnet chain spec, your signing key, the public peers, and `--follow`:

```bash
tempo node \
  --follow=wss://ws.nvnm.testnet.nvnmchain.io \
  --chain=<path-to-nvnm-tempo-testnet-1-chainspec.json> \
  --port=30303 \
  --discovery.port=30303 \
  --consensus.signing-key=./signing.key \
  --trusted-peers=enode://f5826a55ca7c92dc04e6da41e061b0b684ae0338bcdec81ed3213ae8b251308b6870ddafee5128ba16268bdff78f2eba8bda6518d175ddc0cd36c606d604f526@34.150.20.80:30303,enode://2d91f00d8305eb5faf7a002a260ac0d83b6ac4b1a61de7cbdf4021b4476a03360db071e6842f4d3d176c90d9a12c264d77e6c3792634a09a4f483bbceb5c8d70@34.92.172.118:30303
```

- `--follow` syncs certified blocks from the public WebSocket endpoint. Without it, a non-validator node connects to peers but stays at block `0`.
- `--trusted-peers` connects your node to the execution P2P network, which carries transactions, not blocks.
- `--consensus.signing-key` only gives your node a consensus P2P identity. A non-validator node never signs blocks.

<Warning>
  Keep `signing.key` private — never share it or paste its contents. To encrypt it at rest, pass `--secret <passphrase-source>` to `generate-signing-key` and `--consensus.secret <path>` to `tempo node`.
</Warning>

# DevNet

`nvnm-tempo-devnet-1` (EVM Chain ID `787222`) is a fork of [Tempo](https://github.com/tempoxyz/tempo) — `reth` execution + Commonware Simplex BFT consensus. <Note title="Closed sandbox devnet — not externally reachable">
  This devnet's P2P port is **not** exposed outside — there is no public load balancer for it. The peers below only work for nodes running inside that cluster network.
